Code Generation

Generate C, JavaScript, Java, or C# source from supported KelpyShark programs.

In addition to running KelpyShark files directly with the interpreter, the compiler can transpile your code to other languages. Each backend supports a defined subset of the language. The compiler reports unsupported constructs before writing a target file.

Java codegen

The Java backend emits Java 11-compatible source for top-level functions, control flow, collections, and supported built-ins. It also accepts Java-style classes containing static methods. These are emitted as nested helper classes; methods use dynamic Object signatures even when the KelpyShark source includes declared types. Imports, instance methods in Java-style classes, and nested functions are rejected by the checked CLI path.

KelpyShark
@Deprecated
public class Main {
    public static int addNumbers(int num1, int num2) {
        return num1 + num2;
    }

    public static void main(String[] args) {
        System.out.println("The sum is: " + addNumbers(5, 10));
    }
}

print Main.addNumbers(2, 3)

The Java generator emits the @Deprecated marker, but drops other annotations and annotation arguments. In the interpreter, annotations are stored as metadata and do not perform Java annotation checks. Class fields, constructors, inheritance, interfaces, and method overloading are not supported. To run the generated source, compile it with javac and launch the generated Program class.

Shell
kelpyshark build hello.ks --target java --output hello.java
javac hello.java
java Program

C# codegen

The C# backend emits source for top-level functions, control flow, collections, and supported built-ins. Classes, imports, instance methods, and nested functions are rejected by the checked CLI path.

Shell
kelpyshark build hello.ks --target cs --output Hello.cs
# Add Hello.cs to a .NET console project, then run dotnet run

Other targets and limitations

The JavaScript backend supports classes and instance methods, but rejects imports. The C backend supports a smaller subset. Standard-library module imports are not translated by any generated target. Use the interpreter when a program needs unsupported syntax or library behavior.

Tip — Run kelpyshark build first to verify that the selected target accepts the program. The generated source is intended for review and compilation with that target's toolchain.
