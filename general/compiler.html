Compiler Architecture

How source code becomes a running program.

Pipeline overview

Both CLI paths tokenize and parse the source. run then evaluates the syntax tree with the interpreter. build checks the tree and sends it to a code generator.

  1. Lexer — text → tokens
  2. Parser — tokens → AST
  3. Build only: semantic analysis — check names and control-flow rules
  4. Run or build — evaluate the program or generate source

1. Lexer (lexer.rs)

The lexer (scanner) reads raw source text character-by-character and produces a flat list of tokens. Each token has a kind (e.g. Ident, Number, String, Plus, If) and a source location (line, column).

Responsibilities:

  • Skip whitespace and comments (# to end-of-line)
  • Recognise keywords vs identifiers
  • Handle string interpolation markers ({$ … })
  • Produce meaningful errors for invalid characters

2. Parser (parser.rs)

The recursive-descent parser consumes the token stream and builds an Abstract Syntax Tree (AST). Each node in the tree corresponds to a language construct (function definition, binary expression, if statement, …).

Key properties:

  • Handles operator precedence via a Pratt parser for expressions
  • Produces rich error messages with line and column info
  • Supports recovery — attempts to continue after an error to report multiple problems at once

3. Semantic analysis (semantic.rs)

After parsing, the semantic analyser walks the AST to catch errors that the grammar alone cannot detect:

  • Names that cannot be resolved
  • return outside a function
  • break / continue outside a loop
  • Duplicate parameter names

4. Code generation / interpretation

For run, the interpreter evaluates the parsed AST. For build, semantic analysis runs first, then one of the code generators writes a target file:

BackendModuleDescription
Interpreter interpreter/ Tree-walking interpreter. Evaluates the AST directly. Used by kelpyshark run.
C codegen compiler/codegen/c.rs Emits C source for a limited subset of the language.
JavaScript codegen compiler/codegen/javascript.rs Emits JavaScript source for a supported subset, including classes and instance methods.
Java codegen compiler/codegen/java.rs Emits Java source for a supported subset. A JDK is needed to compile the generated file.
C# codegen compiler/codegen/cs.rs Emits C# source for a supported subset. The .NET SDK is needed to compile it.

kelpyshark build writes the selected source file. It does not call the target compiler or create an executable. See Code Generation for target-specific limits.

Error handling

Lexer and parser errors can occur in either command. Semantic-analysis and target-generation errors occur during build. The CLI prints errors to the terminal, and some include a source location.
