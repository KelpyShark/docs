Throwing Errors

Signal problems with throw.

Sometimes you want to raise an error — when invalid data arrives, a precondition isn't met, or an operation simply can't proceed. Use the throw keyword to signal that something went wrong.

Basic throw

throw takes a string that describes the error:

 throw.ks
def sqrt(n) {
    if n < 0 {
        throw "Cannot take square root of a negative number"
    }
    # real implementation…
    return n ^ 0.5
}

try {
    print(sqrt(9))
    print(sqrt(-4))
} catch (e) {
    print("Error: {$e}")
}
Output
3
Error: Cannot take square root of a negative number

Throw for input validation

Validate arguments at the start of a function to catch misuse early:

 validate.ks
def create_user(name, age) {
    if type(name) != "string" { throw "name must be a string" }
    if len(name) == 0         { throw "name cannot be empty" }
    if type(age)  != "number" { throw "age must be a number" }
    if age < 0 or age > 150   { throw "age out of range" }

    return { "name": name, "age": age }
}

try {
    let u = create_user("Alice", 30)
    print(u["name"])
} catch (e) {
    print("Validation error: {$e}")
}

try {
    let bad = create_user("", 30)
} catch (e) {
    print("Validation error: {$e}")
}
Output
Alice
Validation error: name cannot be empty

Throw inside a class

Classes commonly throw errors to protect their internal state:

 class-throw.ks
class Stack {
    def new() {
        self.items = []
    }

    def push(item) {
        push(self.items, item)
    }

    def pop() {
        if len(self.items) == 0 {
            throw "Cannot pop from an empty stack"
        }
        return pop(self.items)
    }
}

let s = new Stack()
s.push(10)
s.push(20)
print(s.pop())   # 20

try {
    s.pop()
    s.pop()   # stack is now empty
} catch (e) {
    print("Stack error: {$e}")
}
Output
20
Stack error: Cannot pop from an empty stack
Warning — An uncaught throw will terminate the program. Always wrap risky calls in try / catch when there's a chance an error might be thrown.

What you learned

  • throw "message" raises an error with a custom message
  • Execution stops at the throw line and jumps to the nearest catch
  • Use throw to enforce preconditions and validate input
  • If uncaught, a thrown error crashes the program
