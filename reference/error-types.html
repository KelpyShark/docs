Error Types

Errors that can be raised by the runtime or by user code.

When an error occurs in KelpyShark, the runtime produces an error message string. This string is available as the variable inside a catch block. Common runtime error messages are described below.

Runtime errors

Error message Cause
Division by zero Any expression that divides by 0
Index out of bounds Accessing a list index that doesn't exist
Undefined variable: <name> Using a variable before it has been declared
Undefined property: <name> Accessing an attribute that was never set on an instance
Cannot call <type> Attempting to call something that is not a function or method
Type error: expected <type> An operator or function received an unsupported type
Stack overflow Infinite or deeply recursive function calls
Key not found: <key> Accessing a dictionary key that doesn't exist
Cannot convert <value> to number num() called on a non-numeric string
File not found: <path> io.read() or io.delete() on a missing file
Invalid JSON json.parse() received malformed JSON
HTTP error: <status> Network-level failure (connection refused, timeout, etc.)

User-thrown errors

Any string passed to throw becomes the error message. There is no fixed set of user error types — you define your own messages:

 user-errors.ks
def divide(a, b) {
    if b == 0 { throw "divide: denominator must not be zero" }
    return a / b
}

try {
    print(divide(10, 0))
} catch (e) {
    print("Caught: {$e}")
}

Inspecting errors

Because error messages are plain strings, you can check them with contains() or starts_with():

 inspect.ks
try {
    let x = badList[99]
} catch (e) {
    if e.contains("out of bounds") {
        print("List index issue — check your index!")
    } else {
        print("Unknown error: {$e}")
    }
}
